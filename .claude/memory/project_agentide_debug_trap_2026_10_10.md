2026-10-10: Donald reported the freeze again (Claude sends something to AgentIDE, a line gets selected in ST, GhostShell stays in its paint-paused state although the conversation continues). It did not happen later that day. I set `"debug": true` in `%APPDATA%\Sublime Text\Packages\User\AgentIDE.sublime-settings`; AgentIDE then prints every incoming message and reply (first 300 chars) as `[AgentIDE] <- #id ...` in Sublime's console (memory only).

Code facts (read, not yet proven as the cause): the only AgentIDE code that creates a selection is `context.open_file` -> `_select_when_loaded` (tool `openFile` with `startText`, `endText`, `selectToEndOfLine`), `lib/context.py` lines 388-411; it opens the file with `window.open_file`. GhostShell pauses repaints while the tab view has a non-empty selection (`_selection_paint_blocked`, `ai_terminal.py` about line 4985) and is meant to release after `_SELECTION_PAINT_BLOCK_MAX_S = 2.5` s; in his freezes it apparently did not release, so two defects are possible: what makes the selection, and why the 2.5 s release fails. Earlier freezes always selected the 24 characters " Do you want to proceed?" (the first line of a permission prompt), which is a screen line, not a file text. See [[ghostshell-phantom-selection-console-read-2026-10-08]].

**Console-reader test, same afternoon (build 4215, sublime-mcp 1.12.2 guard in place):** a watcher thread (eval_python, `sublime._cs_log`, polls every 30 ms, dies when Sublime restarts) recorded any non-empty selection in the Claude view while I ran each reader once: `get_console_log`, `get_console mode=captured`, `get_output_panel name=Console`, `get_console mode=visible`, `get_console_full`, `get_console_win`, `get_console mode=auto`. Result: no selection appeared in any run (log empty, active panel None afterwards). During a visible capture the active view briefly becomes the console and AgentIDE sends `selection_changed` with viewName "untitled", then the Claude tab again; no selection. NOT tested: a permission prompt on screen during a capture (the freezes always had the " Do you want to proceed?" line selected); one pass each proves little. The AgentIDE debug log also showed what Claude Code sends around each edit permission prompt: `closeAllDiffTabs`, `openDiff` (tab "[Claude Code] <file> (hash)"), `close_tab`, `getDiagnostics`: a candidate trigger that is not a console read. Output of `get_console_full`/`win` is 18 KB: use `tail` or captured mode to keep output small.

**Donald's observation (2026-10-10):** when the console box becomes the active view during a capture, AgentIDE reports it to Claude and the CLI shows "[Now in untitled]" (two `selection_changed` per capture: "untitled", then the Claude tab; `_send_view_state` sends the no-file placeholder for any view without a file name, widgets included). Possible one-line change (NOT made, he said "wouldn't mess with that yet"): in `agent_ide.py` `_send_view_state`, return early when `view.settings().get("is_widget")`. Whether this noise has anything to do with the freeze is unknown.

**How to apply:** when he says it froze, do not touch the tab; read the console with `get_console mode=captured` for the `[AgentIDE] <-` lines just before, check the selection of the Claude view and `term._paint_block_since`; then set `"debug": false` again (it prints message text, so do not leave it on for long).
